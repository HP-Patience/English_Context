# 多用户学习与互动设计规格

## 1. 目标

ContextVocab 从当前固定单用户使用扩展为由一个管理员维护的多人学习应用：管理员创建朋友账号，现有学习数据归管理员本人，朋友拥有独立的学习与复习进度；双方可以在受限关系内进行学习互动。

本规格覆盖账号、数据隔离、后台管理、五类互动以及同一浏览器切换账号。它不把公网 HTTP 视为安全部署方案；当前 HTTP 仅作为用户明确要求的临时部署约束记录。

## 2. 当前代码事实

- Prisma 已存在 `User` 模型及多组以 `userId` 关联的学习数据。
- `Word`、`Meaning`、`WordGroup`、`StoryCourse`、`StoryLesson` 等内容模型不属于某个用户。
- 运行时多数接口通过 `getLocalUserId()` 使用固定的 `LOCAL_USER_ID`，因此当前实际仍是单用户数据访问。
- 当前登录由环境变量中的单个用户名、密码哈希和 JWT 签名密钥驱动，不是数据库账号登录。
- 故事离线功能会使用浏览器 Cache Storage；退出登录时已有清理缓存行为，扩展后必须保证缓存不会跨账号复用。
- 当前工作区存在未提交的故事功能修改；本功能不得覆盖或回滚这些修改。

## 3. 选定方案

采用“复用现有用户模型和 JWT，会话身份改为数据库账号”的渐进式改造：

- 在数据库中保存账号凭据、昵称、角色和状态。
- 登录成功后，JWT 的主体标识数据库用户，而不是固定环境变量用户名。
- 服务端从当前会话解析 `userId`，所有用户数据查询和写入都使用该身份。
- 保留现有 Prisma、Next.js App Router、密码哈希和 JWT 依赖。
- 不引入第三方身份提供商、邮件系统或公开注册流程。

不采用：

- 第三方登录或托管认证：当前只有管理员和朋友两个使用层级，引入服务商会增加配置、部署和迁移成本。
- 继续在每个接口中传入用户 ID：客户端可伪造该值，不能作为权限边界。
- 为现有每日目标、故事完成等数据重复创建一套统计数据：排行榜和打卡优先从已有学习记录派生。

## 4. 角色和账号规则

### 管理员

- 当前只有一个管理员，即现有 `local-user` 数据的所有者。
- 可以创建、启用、停用、重置密码和永久删除账号。
- 可以查看用户汇总统计和控制统计开放。
- 不读取用户保存的 LLM/TTS 密钥，不直接修改用户详细学习记录。

### 普通用户

- 由管理员创建，不提供公开注册。
- 拥有自己的学习、复习、故事和设置数据。
- 当前不提供自行修改密码功能。
- 可以退出后使用另一个账号登录。

### 创建和删除

- 创建字段：用户名、昵称、初始密码。
- 用户名唯一且用于登录；昵称用于页面和互动展示。
- 管理员重置密码时覆盖旧密码哈希，不显示旧密码。
- 删除账号必须二次确认，并永久删除该账号及所有个人学习数据、消息和互动记录；公共内容不删除。
- 删除操作必须在服务端按账号身份执行，不能依赖客户端传入的关联记录列表。

## 5. 数据归属和隔离

### 公共内容

所有账号共享：

- 单词
- 词义
- 词表分组
- 已发布故事课程及课程内容

### 个人学习数据

按 `userId` 隔离：

- `UserWord`、`UserWordMeaning`
- 复习会话和复习日志
- 每日目标与学习统计
- 故事课程、段落、步骤、整课完成记录
- 故事词复习进度和强化记录
- 故事段落书签
- 兴趣、每日目标、LLM/TTS 配置
- 个人离线快照和浏览器缓存

每个用户数据接口必须从服务端会话取得当前用户，不接受客户端传来的用户 ID 作为权限依据。

### 既有数据迁移

- 当前固定 `local-user` 数据迁移到管理员账号。
- 新朋友账号不复制管理员学习数据，从空白进度开始。
- 公共内容不迁移、不复制。
- 数据库结构变更必须单独准备生产数据库迁移、兼容窗口和恢复方案；不以 `prisma db push` 代替生产部署。

## 6. 登录、会话和账号切换

- 登录接口校验数据库账号状态和密码哈希。
- 停用或删除的账号不能创建新会话。
- 会话 Cookie 继续使用 HttpOnly、SameSite 和现有 JWT 机制；JWT 主体必须能稳定映射到数据库用户。
- 登录接口保留现有登录限流能力。
- 第一版界面只提供“退出登录 → 登录另一个账号”，不做多账号快捷切换和记住多个账号。
- 账号切换后清理当前用户的 API 响应缓存、故事离线缓存和相关浏览器状态，再加载新账号数据。
- 离线快照和缓存键必须包含用户身份或在切换时可靠清理；不能因为课程内容相同而复用另一个用户的进度快照。

## 7. 管理后台

后台最小页面和能力：

- 用户列表：用户名、昵称、状态、创建时间、最近活动概览。
- 创建用户。
- 启用 / 停用用户。
- 重置密码。
- 永久删除用户。
- 查看用户汇总统计。
- 为用户开启或关闭统计分享。

后台不提供：

- 公开注册审核。
- 多级管理员权限。
- 管理员读取 LLM/TTS 密钥。
- 管理员逐条修改用户掌握度、复习结果或故事进度。

## 8. 互动范围

互动关系限制为“管理员与其直接创建的普通用户”。普通用户之间暂不互相互动；不建立全站公开社区。

### 8.1 自动打卡

- 复用每日目标完成状态。
- 用户当天学习量达到每日目标后自动记为完成。
- 不提供只点击按钮就完成打卡的旁路。
- 打卡状态可用于共同挑战、排行榜和个人统计。

### 8.2 五维排行榜

提供五个独立的排行榜视图，不合并为综合分数：

1. 本周有效学习天数
2. 本周学习单词数
3. 本周复习次数
4. 连续学习天数
5. 故事课程完成度

排行榜只显示被管理员允许分享的用户；不公开具体错词、详细复习日志或个人配置。排行榜指标优先从现有每日目标、复习日志、故事完成记录和当前课程进度派生。

### 8.3 共同挑战

- 管理员创建挑战。
- 同时只能有一个进行中的挑战。
- 管理员和指定朋友账号自动成为参与者，不建立复杂的加入审批流程。
- 挑战可以使用学习天数、学习单词数或课程完成度作为目标。
- 挑战只汇总进度，不修改用户正式掌握度、复习间隔或故事进度。

### 8.4 消息和固定鼓励

- 支持管理员与朋友之间的异步文字消息。
- 支持未读 / 已读状态。
- 支持固定鼓励表情或预设短语。
- 第一版不做实时长连接、图片、文件、语音、群聊和复杂消息线程。

### 8.5 互相出题

- 任一参与者可以选择 1–10 个单词发送小测验。
- 接收者查看词义并完成一次小测验。
- 结果只属于互动记录，不改变接收者正式掌握度、SM-2 参数或复习计划。
- 第一版不做自定义题目、截止时间、图片题、复杂题型和自动生成题库。

## 9. 统计分享和隐私

- 管理员可以逐个账号开启或关闭汇总统计分享。
- 分享内容限于学习数量、完成天数、连续学习、排行榜指标和挑战进度。
- 关闭分享后，朋友看不到该账号的统计和排行榜数据；管理员仍可在后台查看必要的汇总管理信息。
- 详细错词、复习答案、完整学习日志、LLM/TTS 配置和 API Key 不进入互动接口。

## 10. 部署约束

当前明确保留服务器 IP + HTTP 的临时部署方式，仅限熟人测试。该约束不等于安全认证方案：公网 HTTP 可能暴露密码和登录会话。

实现时仍必须保留：

- 密码哈希，不存明文密码。
- HttpOnly 会话 Cookie。
- 登录限流。
- 服务端授权检查。
- 不在管理员页面或 API 响应中返回 API Key。

HTTPS 不纳入当前代码改造范围，但在朋友通过公网正式使用前应作为发布阻塞项处理。

## 11. 实现分片

虽然产品要求五类互动一次交付，但实现必须按依赖顺序拆成以下垂直切片，避免先做没有可靠身份边界的互动接口：

1. 数据库账号、角色、状态、密码哈希和登录会话。
2. 将所有现有用户数据路径从固定用户改为当前会话用户，并完成既有数据迁移方案。
3. 管理后台的账号生命周期和汇总统计。
4. 同一浏览器切换账号、缓存清理和故事离线隔离。
5. 打卡、五维排行榜和共同挑战。
6. 异步消息、固定鼓励和不影响正式进度的单词小测验。

## 12. 验收条件

- 管理员现有学习进度在迁移后保持不变。
- 新账号无法读取或修改管理员的普通学习、复习、故事、书签和配置数据。
- 管理员和朋友同时操作时，写入只影响各自的 `userId` 数据。
- 停用账号不能登录；删除账号后其个人数据不再可访问，公共词库和故事课程仍正常工作。
- 同一浏览器退出管理员后登录朋友账号，不显示管理员的 API 缓存或离线故事进度。
- 普通学习和故事学习原有流程继续可用。
- 达成每日目标后能自动产生打卡状态。
- 五个排行榜指标结果与已有学习数据一致，且不生成综合分数。
- 共同挑战、消息、固定鼓励和小测验只能在允许的管理员—朋友关系内访问。
- 小测验不会修改正式掌握度、复习间隔或故事复习轮次。
- 运行时测试、相关 Vitest 测试、类型检查和 lint 结果能够区分本次新增问题与仓库既有问题。

## 13. 不在本次范围内

- 邮箱注册、邮箱找回密码、第三方登录。
- 多管理员和细粒度 RBAC。
- 全站公开社区、好友申请、群组和陌生人互动。
- 实时聊天、推送通知、图片 / 文件 / 语音消息。
- 用户自行修改密码。
- 将互动小测验自动纳入正式复习调度。
- HTTPS 和域名部署改造。
